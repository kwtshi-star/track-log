# Lane Log（デプロイ手順）

家族全員がどこからでもアクセスできるように、**Vercel単体**（外部のデータベースサービスへの登録なし）で公開する手順です。

データの保存にはVercel自身が提供する**Vercel Blob**（ファイル保存機能）を使います。Supabaseのような「一定期間アクセスがないと自動的に一時停止し、手動で再開が必要」という仕組みが存在しないため、運用の手間がありません。

所要時間の目安：10〜15分（初めてでも）

---

## 全体像

- **Vercel**：このアプリ（画面とAPI）を動かす場所。GitHubと連携すると自動でデプロイされる。
- **Vercel Blob**：記録データ（1つのJSONファイル）を保存する場所。Vercelの「Storage」タブから数クリックで作成でき、外部サービスへの別途サインアップは不要。
- **合言葉（パスワード）**：ネット上に公開されるので、家族しか入れないように簡単なパスワード保護をかけています。

---

## 1. コードをGitHubに置く

1. GitHubでアカウントを作成し、新しいリポジトリ（例: `lane-log`）を作成。
2. ダウンロードしたこのフォルダの中身一式をそのリポジトリにアップロード（GitHubの「Upload files」機能でドラッグ＆ドロップでも可）。
   - フォルダ自体ではなく、フォルダの**中身**（`app`、`lib`、`package.json`など）をリポジトリ直下にアップロードしてください。

---

## 2. Vercelにデプロイする

1. https://vercel.com にアクセスし、GitHubアカウントでログイン。
2. 「Add New → Project」から、先ほどのGitHubリポジトリを選択してインポート。
3. 「Environment Variables」に `APP_PASSWORD`（家族で使う合言葉・好きな文字列）を追加して「Deploy」を押す。
   - `BLOB_READ_WRITE_TOKEN` は次の手順でBlobストアを作成すると自動的に追加されるので、この時点では未設定でも問題ありません。

---

## 3. Vercel Blobを作成する

1. デプロイが終わったら、プロジェクト画面上部の **Storage** タブを開く。
2. 「Create Database」から **Blob** を選択する。
3. ストア名を入力して作成する（外部サイトへの遷移やサインアップは発生しません。すべてVercelのダッシュボード内で完結します）。
4. 作成すると、自動的にこのプロジェクトへ `BLOB_READ_WRITE_TOKEN` という環境変数が追加されます。
5. プロジェクト画面の「Deployments」タブから、最新のデプロイの「...」メニュー→「Redeploy」を実行し、環境変数を反映させる。
6. 発行されたURL（`https://lane-log-xxxx.vercel.app` のような形）にアクセスし、設定した `APP_PASSWORD` を入力すればログイン完了です。

---

## 以前のSupabase版にデータが入っている場合（移行手順）

Supabase版ですでに記録を入力している場合、次の手順でVercel Blob版にそのままデータを移せます。**移行が終わるまでSupabaseのプロジェクトは削除しないでください。**

1. Vercelのこのプロジェクトの「Environment Variables」に、以下の2つを**一時的に**追加する（値はSupabaseの `Project Settings → API` で確認できる、以前メモしたものと同じ）。

   | Key | Value |
   |---|---|
   | `MIGRATE_SUPABASE_URL` | 以前使っていたSupabaseの Project URL |
   | `MIGRATE_SUPABASE_SERVICE_KEY` | 以前使っていたSupabaseの service_role キー |

2. 追加後、「Deployments」タブから最新のデプロイを「Redeploy」する。
3. いつも通りブラウザでアプリを開き、`APP_PASSWORD` でログインする。
4. ログインした**同じブラウザのタブ**で、アドレスバーに次のURLを入力してアクセスする（`あなたのアプリのURL`部分は実際のものに置き換える）。

   ```
   https://あなたのアプリのURL/api/migrate-from-supabase
   ```

5. 画面に次のようなJSONが表示されれば成功です。

   ```json
   { "ok": true, "message": "移行が完了しました。...", "childrenCount": 2, "recordsCount": 15 }
   ```

   - `childrenCount`（子供の人数）・`recordsCount`（記録の件数）が想定通りか確認してください。
   - もしBlob側に既にデータがある状態でこの手順を行った場合はエラーになります。上書きしてよければ、URLの末尾に `?force=1` を付けて（例: `.../api/migrate-from-supabase?force=1`）もう一度アクセスしてください。

6. トップページを再読み込みし、以前の記録が表示されることを確認する。
7. 確認できたら、**`MIGRATE_SUPABASE_URL` と `MIGRATE_SUPABASE_SERVICE_KEY` をVercelの環境変数から削除**し、再デプロイする（もう使わない認証情報を残しておかないため）。

## 更新したいとき

コードを直したい場合は、GitHubリポジトリの中身を更新するだけで、Vercelが自動的に再デプロイしてくれます。

## ローカルで試したいとき（任意）

```bash
npm install
cp .env.example .env.local   # 値を埋める
npm run dev
```

`http://localhost:3000` で確認できます。

## CSVからの復元・追加について

設定画面から、このアプリ自身が書き出したCSV（`lanelog_{子供の名前}_{日付}.csv`）を読み込んで、記録を復元・追加できます。

- ファイル名から子供の名前を自動で判定します（例: `lanelog_さき_2026-09-06.csv` → 「さき」）
- 同じ名前の子供が既にいれば記録を追記、いなければ新しい子供として自動作成します
- 複数ファイルを一度に選択して、まとめて取り込めます
- Supabase版など以前の環境で書き出したCSVもそのまま使えます

## 動画の保存について

このアプリは動画ファイル自体をアップロードしません。保存しているのは動画への**リンク文字列だけ**なので、Blobの無料枠を圧迫する心配はありません（数千件記録してもごくわずかな容量です）。

動画自体は次のどちらかに置き、そのリンクを「動画リンク」欄に貼ってください。YouTubeまたはGoogleドライブのリンクであれば、記録カードを開いたときにその場で再生できます（自動で埋め込み表示されます）。

- **YouTube（限定公開）**：アップロード後、公開設定を「限定公開」にする。リンクを知っている人だけが視聴可能。どの端末でもスムーズに再生でき、容量も気にしなくてよい。
- **Googleドライブ**：共有設定を「特定のユーザーのみ（家族のGoogleアカウント）」にすると、限定公開よりさらに閉じた形で共有できる（見る側もログインが必要）。無料枠は15GB（Gmail・写真と共通）。

家族以外に見られたくない場合は、限定公開よりも「特定のユーザーのみ」共有のGoogleドライブの方が安全です。

なお、YouTubeの動画は記録カード内で0.5倍・0.25倍のスロー再生ができます（スタートの反応や踏み切りの瞬間の確認に便利です）。Googleドライブの動画はこのアプリからは再生速度を変更できないため、スロー再生をしたい動画はYouTubeに置くことをおすすめします。

## セキュリティについて

- 合言葉（`APP_PASSWORD`）はごく簡易的な保護です。強固な認証ではないので、推測されにくい文字列にしてください。
- `BLOB_READ_WRITE_TOKEN` は絶対に公開リポジトリのコードに直接書かず、必ずVercelの環境変数として設定してください（このコードはすでにその前提で書かれています。Storage経由で作成した場合は自動的にこの原則が守られます）。

## データの保存容量・整合性について

- Vercel Blobの無料枠（Hobbyプラン）は、ストレージ1GB・転送10GB/月。テキストのみのこのアプリの用途では十分すぎる余裕があります。
- 同じファイルを上書きする方式のため、読み込み時は毎回キャッシュを迂回して最新内容を取得するようにしています。ただし家族の別端末でほぼ同時に編集した場合は、最後に保存した内容が優先されます（同時編集を頻繁に行わない使い方であれば問題になりません）。
